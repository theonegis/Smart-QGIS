# 任务契约与恢复设计

Smart-QGIS 的默认 `reliable` 模式把 GIS 修改操作放入有状态任务：宿主模型负责理解需求、选择算法和与用户交互；服务端负责基本检查、串行执行、SQLite 日志及恢复。模式选择和具体调用见[可靠模式用法](reliable-usage.md)。`legacy` 是无任务日志的直接工具模式，不提供任务契约或恢复保证。

## 边界

- 任务开始时检查输入数据和路径；处理前依据公开工具 schema、当前安装的 QGIS 算法帮助与原生 preflight 检查参数。
- 结果提交前检查声明格式、可打开性、CRS，以及用户明确提出的额外验收要求。通用契约不强加案例专属科学阈值。
- 标准地图默认保留图名、图例、比例尺与坐标标注。仅在用户明确要求时省略某一项；视觉布局仍需人工或任务专用评价检查。
- 无文档默认值且无法由目标/已检查数据唯一确定的必选参数，持久化为结构化问题并向用户询问，不由模型猜测。
- 模型思考超时属于客户端；MCP 只控制 worker 操作超时。任一超时或纠错上限都要求真实用户干预，不自动盲目重放。

## 执行与恢复

```text
MCP 客户端（模型、对话、审批）
       │
       ▼
task_start / prepare_algorithm / task_execute
       │
       ▼
任务协调器 ── SQLite 日志、逻辑资产、检查点
       │
       ▼
串行 QGIS bridge ── 独立 PyQGIS worker
       │
       ▼
产物基础校验 → 提交，或保存错误供同任务修复
```

`task_start` 锁定最小任务目标与输入；标准工作流和已批准计划的下一动作由服务端持有，客户端只调用无参数 `task_execute`。通用 Processing 使用精确算法 ID 调用 `prepare_algorithm`，按实时帮助规范化参数并创建一步执行计划。工作流按步骤增量推进，成功后保存检查点。

失败但未提交的步骤可以重新准备；已提交但经证实错误的产物先失效，再替换生产步骤。失效保留旧尝试证据，避免把错误产物当成当前结果。服务重启后以原任务 ID 调用 `task_resume`；`task_diagnose` 只读，不执行也不恢复。相同回答与已提交动作的重发具有幂等保护；不要手工改 SQLite、虚构用户回答或另建任务来掩盖失败。

每个任务目录含 SQLite 与相关检查点/产物。服务启动时自动清理已完成或取消且超过 10 天、阻塞且超过 60 天的整任务目录；活跃/待答/持锁任务不清理。期限可通过启动参数调整，`0` 关闭对应类别的清理。

## 安全与适用范围

这是可信本地用户的后台 GIS 工具，不是远程多租户执行沙箱。处理算法来自当前 QGIS 注册表；安装的 provider、算法 ID 和参数随环境变化。可靠恢复要求输入、产物及运行环境仍与记录相符，不承诺跨 QGIS 版本原地迁移。外部数据库写入或未适配的副作用不能仅凭本地检查点视为可安全回滚。

任务专用的全栅格科学正确性和地图美观需要由任务自己的评价层核验；它们不应被写成所有普通用户任务的隐藏强制契约。
