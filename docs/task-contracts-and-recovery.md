# Smart-QGIS 任务契约与故障恢复技术方案

> 状态：实现进行中，尚未完成整体验收。工作树默认启用契约门槛；`--execution-mode legacy` 仅保留为论文旧接口消融基线，不承担兼容承诺。本文仍包含未完成的目标设计，不能将接口清单或测试计划视为全部已验收。不创建版本、不发布。

## 实现进度

已加入并通过当前自动化测试的能力：

- 类型化任务/步骤契约：自动基础验收、用户附加要求覆盖、未知资产检查、必需约束防弱化及重采样冲突检测；没有附加要求时任务契约可为空。
- SQLite 任务日志：跨进程排他锁、完整输入指纹、版本检查、幂等提交记录、待核对尝试、依赖闭包失效。
- GeoTIFF 等常见图像的外部掩膜、辅助元数据、概览与世界文件纳入内容指纹；VRT 递归纳入本地引用与其辅助文件，循环或非本地引用明确拒绝。Shapefile 同时纳入 QPJ 坐标系文件。
- QGIS 私有恢复操作：只读数据检查、内存图层持久化、工程与选择集快照、环境匹配和新 Worker 恢复。
- 真实 QGIS 测试验证了内存图层、选择集、样式和布局跨进程恢复后的地图导出。
- 内存图层快照保留过滤条件及被隐藏的完整数据；过滤结果为空也不丢弃源要素。跨进程恢复后清除过滤可重新访问全部原始要素。
- 公开任务接口与默认执行门槛：拒绝无契约修改、核对步骤参数、分配受控输出路径；兼容模式保留旧工具接口。
- 通用只读 `contract_get` 按需读取已持久化的任务或步骤契约；标准 MCP 新会话恢复测试验证其不依赖旧对话、不修改状态或授权。
- `task_execute` 根据批准步骤直接执行，五个授权字段必填；无需重新生成 GIS 参数，复用原门槛和幂等通道。协议参数错误返回稳定结构化反馈。
- 提交协调器与最终验收入口：通过检查后提交快照；必需检查失败或未验证时不允许完成。
- Worker 丢失响应后的有界重放，以及主进程在文件持久化后、提交前退出后的重新验证与提交。
- 真实进程在执行中、验证中、文件持久化后、数据库提交后退出的恢复测试；已提交后响应异常不降级持久结果。
- 默认关闭的 LangSmith 白名单事件适配；阶段事件关联任务、步骤派生键及尝试 UUID；追踪连接持续失败时仍通过真实 QGIS 保存、重连和导出测试。MCP 入口禁用环境变量隐式触发的 LangChain 完整参数追踪。
- 提供栅格全量/抽样掩膜与值比较、旋转网格对齐、实际几何重叠、图例标签及符号一致性验证器；这些严格检查只在用户明确要求时启用，不再按算法族自动注入。
- 取消后回退已提交工程，显式确认恢复才继续；模拟磁盘失败、产物篡改和环境不一致时阻止不安全提交/恢复。
- 本地模型按需契约 schema 查询与精简字段诊断；内部强类型校验仍保持启用。
- 默认可靠 MCP 接口由紧凑任务工具、只读算法发现和统一 `prepare_algorithm` 组成。`task_start` 自动检查输入并锁定最小任务契约；标准工作流只返回 32 位 action handle 给 `task_execute_next`；通用 Processing 的规范化结果和待答问题持久化到 SQLite。
- 契约修订后可显式重新验证具有持久输出的旧步骤；验证失败保持失效，验证通过复用原产物，不新增执行尝试。纯状态步骤仅在其原始工程、补充状态和指纹仍为当前检查点时支持重新验证；后续替换的检查点不能据此复用。显式输入新版本接纳已加入事务化失效与回退。
- `task_invalidate` 处理最终验收失败的已提交结果：原子更新失效闭包与恢复检查点，保留旧文件，允许修正步骤重用交付物逻辑 ID。合成案例验证恢复后通过原契约且有效上游不重算；Codex 陕西原失败任务也已在契约版本保持不变的条件下修复完成，并通过独立抽样。
- 未提交尝试与输入同时变化时，可通过 `task_revise_inputs(discard_uncommitted=true)` 显式隔离未提交结果，原子接纳输入新版本，并保留独立已提交结果；事务失败时全部回滚。

已补充跨 CRS 边界表达模型；真实案例在两种模型下的全量对照见论文素材，不能混同通过结论。

陕西六阶段 Worker 故障案例已完成；投影顶点边界模型下裁剪全量参考和独立 Horn 坡度参考已通过。原始边界模型下的差异单独保留，不能据此宣称所有科学解释都一致。合成错误 CRS 四组各三次试验已完成，只有检查点加 Codex 修复组完成并通过独立参考；该结论局限于预写契约的单类缺陷。具体计数及运行证据见论文素材。

逐项验证报告及本地 PHASE_TIMING 事件已记录检查和执行阶段壁钟耗时，不依赖远端追踪；写入失败不影响提交。

尚未完成的验收与实现边界：

- Hermes 固定 64K、低推理配置的原任务完整交付仍未通过；不能由标准 MCP 集成测试替代真实宿主自主契约验收。
- 环境匹配覆盖 QGIS、GDAL、Python、Qt、处理提供者以及 NumPy、Shapely、PyProj；缺失验证依赖记录的旧检查点同样拒绝自动恢复。当前要求恢复原环境或在新任务中重新计算，不支持旧检查点跨环境原地迁移，也不能静默忽略版本差异。
- 纯工程状态复用只验证原检查点仍被保留的情形；跨后续检查点推断历史状态是否仍成立尚不支持，需要新步骤重新建立状态。
- 论文的契约质量人工审查、多类静默错误/误报统计和隔离性能实验尚未全部完成。外部审查类检查仍返回“未验证”，必需项不能据此完成任务。

Codex 原任务恢复已完成；Hermes 历次失败和超时继续计入原任务成本，不只报告最后一次接续。完整目标仍需逐项审查，当前证据索引见文末。

当前测试通过不等于技术方案全部完成；在上述缺项补齐前不发布版本。当前调用约定见[可靠任务使用说明](reliable-usage.md)。

## 1. 目标与架构决策

发布的 `2.0` 标签通过 LangChain StructuredTool 与 Pydantic 校验调用参数，以串行桥接器驱动独立的 QGIS Worker。这种参数校验不是本文的任务语义契约；旧直接工具实验模式中的修改调用不是事务，Worker 超时或退出后不能自动恢复未保存状态。架构见[开发说明](development.md)，已有案例验收见[测试说明](testing.md)。

下一阶段的目标是：从用户目标与真实数据自动形成可检查的契约，在任务失败后恢复已验证状态，并由宿主 Agent 根据证据修订执行方案。

### 已确定的技术选择

- 默认强制任务契约；显式 `--execution-mode legacy` 是无契约、无恢复的旧直接工具实验基线。
- Codex、Hermes 等宿主 Agent 生成契约并提出语义修复方案。Smart-QGIS 不创建模型、不读取模型凭据，不要求用户手写契约。
- SQLite 与本地文件实现恢复。第一阶段不引入 LangGraph；LangSmith 为默认关闭的可选追踪适配。
- 保持无 GUI、QGIS 独立 Worker、主线程执行及修改操作串行化的架构。
- 首期可靠执行范围为本地文件数据、服务端管理的输出和可持久化工程状态。外部数据库写入及具有未适配副作用的算法，不进入可靠执行通道。
- 技术方案、示例和公开测试使用占位路径及合成数据。真实案例数据、凭据和原始客户端日志不提交 GitHub。

```text
宿主 Agent：理解目标、生成契约、修订方案
                  │ MCP
任务控制层：契约门槛、状态版本、幂等、恢复预算
          │                      │
SQLite 与产物目录          可选 LangSmith 追踪
          │
串行 QGIS Bridge → Worker → Processing / Project / Layout
          │
验证结果 → 提交检查点，或返回故障证据给宿主
```

## 2. 自动契约生成与执行门槛

### 2.1 生成过程

1. Agent 调用 `task_start`，提交用户目标、输入、交付物及明确的附加要求。
2. 服务端检查全部输入并确定数据类型，记录不可静默覆盖的目标原文，然后锁定最小任务契约。
3. 标准任务持久化下一动作和固定参数并返回 32 位 opaque handle；Agent 只调用 `task_execute_next(handle)`。
4. 没有标准工作流时，Agent 确定精确算法 ID 并调用 `prepare_algorithm`；服务端查询参数结构并生成持久化的结构化澄清问题。
5. Agent 根据反馈修订；通过后锁定契约版本。
6. 每个正式操作执行前，提交对应步骤契约，检查通过后才允许执行。

任务契约定义最终目标；步骤契约随实际工作流增量生成，不要求 Agent 预先确定完整路径。提示词引导 Agent 完成准备工作，执行门槛负责阻止绕过契约的调用。

服务端只能保证契约阶段不可跳过，不能保证宿主转述的目标与用户原意完全一致，也不能保证 AI 推导出的约束完备。文档和实验必须保留这一边界。

### 2.2 契约内容与来源

任务契约记录目标、交付物、输入版本、验收条件、未解决歧义及版本。步骤契约记录操作、输入依赖、前置条件、输出要求和检查项。

每个检查项包含：

- 验证器标识及参数；
- 约束来源：用户要求、算法规则或方法假设；
- 证据引用与适用条件；
- 必须满足或建议满足；
- 验证范围：全量、抽样或外部审查。

检查项使用注册验证器，不允许提交任意 Python 代码。无法自动验证的要求明确标记为“未验证”；必须满足的要求未验证时，不能宣称任务完成。抽样检查通过不代表全量正确。

输入版本、逻辑引用、工具参数及输出格式/可读性/CRS 等基础检查由系统执行，Agent 不得删除也不必重复。制图默认要求图名、图例、比例尺和地理或投影坐标标注；仅用户明确要求的删除项可记录在 `map_omissions`。其他任务语义只从用户明确要求形成检查；方法假设记为说明而不升级为验收条件。具有实质影响的未解决歧义交回宿主向用户澄清。

### 2.3 契约审查与首期验证器

| 审查层次 | 检查内容 |
|---|---|
| 结构 | 验证器存在，参数类型与必填项正确 |
| 证据 | 引用的数据、字段、单位和元信息确实存在 |
| 覆盖 | 可选审计映射引用必需检查 ID；交付物基础有效性由系统检查，省略映射不增加模型纠错轮次 |
| 冲突 | 不同时要求互相矛盾的处理与结果 |

首期验证器覆盖数据可读性、CRS 与字段、空间重叠、栅格网格与 NoData、几何有效性、产物来源、布局图层关联、图例与渲染一致性，以及导出文件有效性。

裁剪、重投影、缓冲、叠加和地形分析可使用相应验证器，但算法选择本身不自动派生验收规则。数值容差、边缘像元规则和抽样方法只在用户明确要求的检查项中记录；不设通用于全部 GIS 任务的固定误差阈值。

例如，裁剪后的像元一致性检查必须考虑是否重采样；空结果是否有效取决于任务目标；掩膜边缘检查必须匹配实际采用的像元规则。地图文件可读不能代替数据来源与布局内容检查。

契约变更保存新版本、原因和影响范围。不得为让结果通过而自动放宽用户要求；相关结果必须重新验证。

## 3. 接口、状态与持久化

### 3.1 MCP 接口

| 新接口 | 职责 |
|---|---|
| `task_begin` | 创建任务并返回准备阶段上下文 |
| `inspect_data` | 不修改工程地检查输入数据 |
| `task_contract_submit` | 提交或修订任务契约 |
| `workflow_run` | 一次模型调用执行标准地图/工程流程，内部每步仍独立契约、验证和检查点 |
| `step_prepare` | 将常见 GIS recipe 的少量逻辑参数编译为完整步骤契约，并返回预填执行调用 |
| `step_contract_submit` | 提交一个步骤契约并返回预填执行调用 |
| `contract_get` | 只读获取当前任务契约或一个步骤契约，支持无旧对话的恢复 |
| `task_execute` | 使用明确授权上下文执行已批准步骤，避免重复发送 GIS 参数；复用原执行及恢复通道 |
| `task_diagnose` | 返回状态、版本、有效结果及故障上下文 |
| `task_checkpoint` | 建立已验证的工程检查点 |
| `task_validate` | 验证阶段结果或最终交付物 |
| `task_recover` | 核对持久状态并恢复任务 |
| `task_finish` | 全部必需验收项通过后完成任务 |
| `contract_help` | 按需返回契约结构及单项验证器 schema，减少本地模型上下文负担 |
| `task_revise_inputs` | 显式接纳检查过的新内容指纹，事务更新输入版本与受影响结果，保留独立产物 |
| `task_invalidate` | 最终验收失败后失效生产步骤与下游，恢复安全工程状态并保留有效上游 |

可靠模式的公开工具表只保留任务生命周期、输入检查、算法只读发现和图层只读列表。底层修改工具不再对模型公开，但继续作为内部执行目标。`workflow_run` 把标准地图流程压缩为一次宿主调用，内部仍逐步提交；`step_prepare` 覆盖单项常见操作。任务/高级步骤 schema 和验证器目录均按需加载。没有匹配 workflow/recipe 时才使用 `step_contract_submit`。旧直接工具表仅由实验基线 `--execution-mode legacy` 提供，不是新版的兼容层。

可靠模式中的修改工具使用服务端返回的不透明 `continuation_token`。模型只复制 token，不生成状态版本、契约版本或幂等键；服务端从 token 派生这些内部值。同一审批 token 的执行重试返回已提交结果，错误步骤或过时 token 被拒绝。

所有入口按具体 action 分类，统一执行门槛检查，不能只按工具名称区分读写。准备阶段允许只读检查；加载、样式修改、处理和导出均须契约授权。除已提交请求的幂等取回外，旧状态版本请求拒绝执行并返回最新状态。

错误响应包含稳定错误码、故障阶段、可重试性、证据、有效检查点和下一步建议。契约缺失、版本冲突及验证失败均返回可操作信息，而不只是底层异常文本。

### 3.2 状态模型

任务正常状态为：

```text
PREPARING → READY → RUNNING → COMPLETED
```

故障分支进入 `RECOVERING` 或 `BLOCKED`；允许显式 `CANCELLED`。技术问题解除后可恢复，取消不自动重试。

步骤正常状态为：

```text
PLANNED → RUNNING → VALIDATING → COMMITTED
```

失败标记 `FAILED`；因输入或契约变化失效的步骤标记 `INVALIDATED`。进程异常退出时，未提交尝试视为结果未知，必须核对，不能直接认为成功或失败。

任务、步骤和每次尝试分别具有稳定标识。步骤依赖同时包括数据产物及工程状态，例如选择集、过滤条件和布局引用，不能仅依据文件参数推断。

### 3.3 存储和隔离

- 状态根目录默认位于系统用户数据目录，可由 `SMART_QGIS_STATE_DIR` 配置；不放入源码仓库。
- 每个任务独立目录和 SQLite 数据库，保存契约、步骤、尝试、依赖、产物、检查点及故障事件。
- 一个服务进程同一时间仅附着一个任务；切换前持久化当前任务并重建 Worker。
- 对任务目录加跨进程排他锁，防止多个 MCP 进程同时修改同一任务。
- SQLite 是控制状态的权威记录；LangSmith 不是恢复依据。
- 产物使用稳定逻辑 ID；QGIS 运行时图层 ID 通过映射解析。
- 工程检查点包含 QGZ、持久化数据引用、选择集等补充状态、环境版本和验证报告。内存及临时结果必须落盘后才具有恢复保证。
- 本地输入记录完整内容指纹，多文件数据源纳入全部相关文件；恢复和使用前检查变化。输入保持只读，外部并发修改不在保证范围内。
- 在线底图记录服务定义，网络变化和瓦片内容变化不承诺逐像素重现。

## 4. 提交与恢复机制

### 4.1 先验证、后提交

每次修改操作先持久记录执行意图，再写入独立尝试目录。输出及工程状态通过检查后，关闭写入句柄、持久化产物与工程快照，最后在 SQLite 事务中提交引用和新状态版本。

SQLite 事务不能自动覆盖文件系统和 QGIS 内存状态，必须显式处理跨存储提交窗口：

| 故障窗口 | 恢复动作 |
|---|---|
| 执行中崩溃 | 隔离未提交产物，恢复上一个检查点 |
| 文件完成但未提交 | 按持久记录重新验证，满足条件才补齐提交，否则隔离 |
| 已提交但响应丢失 | 重试时返回原结果，不重复产生工程副作用 |

未验证结果不暴露为已提交依赖。工程已被失败操作修改时，重建 Worker 并加载已提交状态。可靠模式中的输出必须由服务端管理，不允许算法覆盖原始输入或绕过产物目录产生未受控副作用。

首期使用较保守的策略：每个修改步骤提交工程快照，大数据产物不可变共享，不重复复制整个栅格。性能优化依据测量结果后续开展。

### 4.2 分级恢复

| 故障或事件 | 默认处理 |
|---|---|
| 临时网络失败 | 首次失败后最多自动重试两次，退避 1 秒、4 秒并加入抖动 |
| Worker 崩溃或超时 | 停止整个进程组，恢复已验证状态；符合安全重放条件时最多自动重放一次 |
| 用户取消 | 停止当前尝试并保留已提交结果，不自动继续 |
| 参数错误或契约失败 | 交回 Agent 提出修复；每步骤最多三次语义修复尝试 |
| 相同输入、参数和故障签名再次出现 | 拒绝无变化的语义修复重试 |
| 输入改变 | 使依赖闭包中的下游结果失效，保留不受影响的结果 |
| 环境版本与检查点不一致 | 阻止自动恢复，要求在当前环境重新验证或重新计算 |
| 外部输入不可用、磁盘写入失败 | 保留证据和已有检查点，等待条件恢复 |

只有输入未变化、操作副作用已受控、无已提交重复结果且前置条件仍成立的步骤，才允许安全重放。

恢复后重新核对产物、输入版本、工程状态及逻辑标识映射。成功启动进程或打开 QGZ 不等于恢复成功。

### 4.3 AI 修复上下文

交回宿主的故障上下文包含：失败步骤与阶段、实际错误、验证证据、有效检查点、可复用结果、失效的下游结果、已尝试方案和剩余预算。

AI 修复只修改执行方案；改变科学含义或用户要求须通过契约修订流程。降低分辨率、改变重采样方法等不能被当作普通技术重试静默实施。

服务端提供恢复能力，宿主负责继续推理；宿主或 MCP 退出后，通过重新连接与 `task_recover` 继续，不承诺客户端关闭后自动唤醒 Agent。

### 4.4 LangSmith

提供可选追踪适配，关联任务、步骤和尝试，记录契约检查、执行、验证、恢复及耗时。默认仅保留本地事件；启用远端追踪时采用字段白名单，过滤凭据和敏感内容。

追踪失败不得影响提交与恢复。服务端追踪不等同于完整宿主模型轨迹；Codex、Hermes 的决策记录需另行关联。

LangSmith 用于诊断与实验分析，不替代 SQLite、产物存储或 QGIS 检查点。第一阶段不使用 LangGraph；后续若引入，也仍须自行实现 QGIS 状态持久化与副作用管理。

## 5. 实施顺序与验收

### 5.1 分阶段实现

1. **执行门槛**：任务状态、只读检查、契约提交、统一调用校验及兼容模式。
2. **恢复底座**：SQLite 日志、独立产物、幂等、工程快照、启动核对与任务锁。
3. **语义闭环**：算法族验证、依赖失效、结构化故障上下文和 AI 修复预算。
4. **观测与实验**：可选 LangSmith、故障注入、真实客户端验收和文档更新。

每阶段完成对应测试再进入下一阶段。现有 `2.0` 标签保持不变，后续代码在 `main` 开发；本文档交付不创建版本、不发布。运行时实现后，更新开发说明与客户端文档，说明默认模式迁移方法和实测范围。

### 5.2 必测场景

- 无契约调用修改工具被拒绝；只读检查仍可使用。
- AI 漏项、引用不存在字段、生成矛盾条件时获得可操作反馈。
- 幂等请求、参数冲突、过时状态、并发恢复均有确定行为。
- 在执行中、验证中、文件持久化后、数据库提交后注入崩溃。
- 覆盖 MCP 重启、Worker 超时、取消、磁盘失败、输入变化和产物缺失。
- 恢复后核对图层、选择集、过滤条件、样式、布局及逻辑 ID 映射。
- 验证局部修复不会重算有效上游；错误恢复不会静默放宽契约。
- LangSmith 关闭或断网时仍可完整恢复；追踪内容不包含测试用敏感标记。
- `legacy` 模式运行原有测试；默认模式运行新增可靠任务测试。

### 5.3 真实案例与研究验收

使用陕西 DEM 流程，在加载、裁剪、重投影、坡度、样式和导出阶段分别注入故障。恢复结果与独立参考结果进行容差感知比较，并检查地图结构；不以 PDF 字节一致作为正确性标准。

Codex 和 Hermes 均使用目标型提示词，要求其自行检查数据并生成契约，不预填完整验收条件。保留另一个明确步骤的执行测试集，区分规划能力与执行可靠性。

论文实验比较无恢复、固定重试、检查点恢复、检查点加 AI 修复四组。报告契约遗漏与错误约束、静默错误检出与误报、恢复正确率、重复计算成本和验证开销。独立参考标准由人工审查与确定性验证共同建立，不使用 Agent 自己生成的契约作为唯一真值。

记录模型、harness、软件环境、数据版本和重复运行次数。不同模型与 harness 的组合不能直接用于单独归因 harness 效果；开发调试任务与最终评测任务分开。

### 5.4 客户端无关的实现约束

Smart-QGIS 是通用 MCP 服务。宿主负责生成契约和提出修复方案，服务端不以 Hermes/Codex 名称分支，不依赖任何宿主私有发现接口，不按模型能力放宽验证。小型或本地模型适配通过所有客户端可用的精简 schema、按需说明和结构化反馈实现。特定宿主的上下文、推理和工具发现配置只进入实验适配器；其收益与服务端通用改进分别报告。标准 MCP 会话测试验证协议行为，多客户端真实任务验证可用性，单一宿主测试不能证明跨客户端性能提升。

## 输入参数前检与结果后检的实施补充

依据用户最新要求，正常流程采用输入/参数前检和产物后检两道检查。前检结合实际数据、算法帮助及 QGIS checkParameterValues，在步骤批准前拒绝错误参数；算法帮助显式给出 `required` 与 `has_default`。只有必选、无默认值且不能由目标和数据唯一确定的实质参数才交回宿主询问用户。宿主应在调用 `step_contract_submit` 前提问；`unresolved_questions` 仅作为拒绝未解决契约的安全兜底，不能用故意失败的提交登记问题。后检只执行格式/可读性/CRS 等基础正确性及用户明确附加要求，不按算法选择强制增加掩膜、网格、像元值、NoData、几何、精度或来源规则。制图基础后检默认含图名、图例、比例尺和坐标标注，只有用户明确要求才允许通过 `map_omissions` 删除。必要的恢复完整性核对仍保留，不当作要求模型反复重新生成契约。

任务创建、契约提交及修改工具的参数/授权/修复错误共用连续三次拒绝的预算，耗尽后阻止修改操作；只读诊断保持可用。已提交且仍有效的幂等请求可以读取原结果，不产生新执行。task_record_guidance 保存用户问答并重开准备纠错窗口，不修改已锁定要求，也不重置执行语义修复预算。任务创建前计数限于当前服务进程，任务建立后持久化到 SQLite；宿主须如实传递用户回答。详见[使用说明](reliable-usage.md#前检后检与停止纠错)。
